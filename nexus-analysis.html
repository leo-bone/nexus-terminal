Nexus Terminal · 项目评估报告

加密货币因子关系终端 · 版本 v3 · 部署于 Cloudflare（nexus.uichain.org）
评估日期：2026-10-01 ｜ 评估依据：源码全量（app.js 490 行 / worker.js 208 行 / index.html 291 行）+ 线上实测
一句话定位：一个"能在中国大陆直连、零成本运行"的多因子加密市场温度计——把 20 个跨市场因子标准化后合成一个综合评分，并可视化因子之间的实时联动关系。

它不是交易终端，也不是数据终端；它的稀缺性不在数据本身，而在可达性 + 整合方式：同类专业工具在大陆基本打不开，而它把分散在行情/情绪/链上/衍生品/宏观五处的信息压进一屏。

一、优点

维度具体表现评价
架构极简单 HTML + 单 app.js + 一个 Worker，无框架、无 npm 构建、无数据库。可直接 file:// 打开或部署任意静态托管。全量仅约 1000 行。强
大陆可达的数据管线所有外部请求经 Worker /api/fetch 白名单代理，绕开 GFW 与浏览器 CORS。实测 Bybit / CoinPaprika / mempool / alternative.me 从 CF 边缘可用。这是最深的一条护城河。核心差异化
多因子可解释融合20 因子分 6 组（核心/情绪/链上/衍生品/宏观/市场/技术），每个因子输出 z-score + 方向信号 + 原始数值，不是黑箱评分。强
因子关系网络力导向图 + Pearson 相关矩阵，把"此刻哪些因子在联动/背离"变成可看的结构。散户工具中少见。差异化
零运营成本Cloudflare 免费额度（Workers + 边缘缓存）完全够用，无服务器、无月费、无运维。强
信息密度高一屏集成：行情条 / 恐惧贪婪 / 技术面板 / 因子评分 / 相关性网络 / 宏观仪表盘 / 链上 / 衍生品 / 回测 / 模拟盘。中上
形成闭环"看（因子）→ 验（回测）→ 试（模拟盘）"完整闭环，且全部本地/免费。中上

二、缺点

按严重度排序。前三条直接影响"这个分数能不能信"。

问题说明严重度
存在"死因子""链上活跃"因子实际恒为中性（mempool 只提供算力，n_tx 被置 null）；"稳定币占比"因子恒显示「—」（CoinPaprika 无该字段）。20 维里有 2 维是空转的。高
宏观用静态中枢DXY 103 / US10Y 4.2 / GOLD 3700 / SPX 7000 / VIX 16 是人工设定的固定基准，不是滚动 z-score。会随时间失真，需人工校准（已修过一次）。高
相关性样本短、跨频相关性基于单次请求的短窗口（如 96 根 1h），且把 1d / 1h / 日频宏观序列直接对齐，未做时间重采样，小样本 + 跨频会造成伪相关。高
数据源单点行情与衍生品全押 Bybit；宏观押 Stooq（免费源，可能限流/改格式）。任一源故障即对应面板瘫掉，无冗余。中高
无持久化 / 无历史纯前端，刷新即重拉；没有历史因子库，因而无法做真正的因子择时回测，相关性也只反映"当下这一刻"。中高
指标口径偏差多空比取 Bybit account-ratio 的账户数占比，而非持仓量多空比，含义与专业口径不同，易被误读。中
文档/标签过期index.html 中链上面板仍标 "CryptoCompare"、衍生品标 "Binance FAPI"、页脚写 "Binance/CryptoCompare/CoinGecko"，与实际 Bybit/mempool/CoinPaprika 不符，损害可信度。中
无用户体系 / 无告警 / 无导出模拟盘存 localStorage，换设备即丢；无阈值提醒（F&G 极值、资金费率异常、评分穿越）；不能导出 CSV/PNG。中
移动端体验差1720px 栅格 + 440px 画布，手机上为硬缩放，未做针对性布局。低

三、竞品格局

Nexus 的直接竞品不是 Bloomberg / TradingView（维度不同），而是"因子 / 情绪 / 链上 / 衍生品"这一类聚合工具。逐类对比：

类别代表产品Nexus 的优势Nexus 的劣势
机构级终端Bloomberg、Kaiko、Amberdata免费、零门槛、大陆可用数据深度/授权/历史长度差一个量级
专业图表TradingView因子融合 + 相关性网络 + 大陆可用图表功能、指标库、社区远不及
链上分析Glassnode、CryptoQuant、Nansen、Arkham免费 + 大陆可用 + 多因子融合链上指标只有"算力"一项，极度单薄
衍生品/爆仓CoinGlass、Coinalyze大陆可用 + 免费 + 融合宏观仅覆盖 BTC、无爆仓图、无多所聚合
情绪/社交Santiment、LunarCrush、The Tie大陆可用 + 与因子融合无社交/新闻情绪，仅 F&G 一项
综合数据站CoinGecko、CoinMarketCap因子关系 + 宏观 + 大陆可用币种覆盖与数据权威性远不及
宏观数据FRED、TradingEconomics、Koyfin免费 + 与加密市场融合宏观深度、更新频率、指标数量有限

结论：Nexus 活在一条"缝隙"里——中国可直连 × 零成本 × 因子关系可视 × 一屏融合。它的每一维度单独拿出来都不如垂直专业工具，但把"可达性 + 整合"叠加后，形成了专业工具也覆盖不到的位置。这也意味着它不能靠数据取胜，只能靠"整合视角 + 可达性"取胜。

四、可改进的地方（按投入产出比排序）

优先级改进项理由 / 预期收益
P0修掉两个死因子链上活跃接可用 n_tx 源、稳定币占比改由 tickers 聚合或 CoinGecko 缓存取。直接让 20 维里空转的 2 维活过来。
P0宏观改滚动 z-score用 /api/snapshot 返回的 series 直接算近 N 日 z，取代人工中枢，一劳永逸、不再失真。
P0相关性做时间对齐计算前按日重采样到共同时间轴，消除跨频伪相关，让"因子关系"这一核心卖点真正站得住。
P1多源冗余 + Worker KV 兜底Bybit 之外加备源；Worker 侧 KV 做只读缓存，源故障时返回上一份可用数据而非空白。
P1数据健康面板显式展示每个数据源的最后成功时间与延迟（现在只有一个状态点），出问题能秒定位。
P1修正标签与文档近乎零成本，直接提升可信度。链路/页脚的数据源标注改为实际来源。
P2建立历史因子库（KV/D1）存每日快照，让相关性与 z-score 有统计基础，并解锁"评分 vs 未来收益"的 IC / Rank-IC 检验——这是把它从玩具变成工具的关键一步。
P2因子权重可调 + 可回溯当前权重是硬编码的（1.2/1.0/…）。让用户调参并回测评分有效性，等于把"拍脑袋的评分"变成"可验证的信号"。
P2阈值告警 + 导出分享F&G 极值、资金费率异常、评分穿越 30/70 时提醒；支持导出 CSV/PNG、分享快照链接。
P3移动端 / 多资产 / 内容层响应式布局；从"BTC 中心"扩展到多币种；叠加"每日因子简报"，形成内容获客层。

五、这个项目对用户有什么帮助

对"你"（开发者 / 运营者）

  • 可复用的个人研究平台：一套自己的加密市场"仪表盘"，可随时间迭代权重与因子。
  • 技术验证载体：Cloudflare 全栈（Workers Assets + 边缘代理）＋ 零构建前端 ＋ 数据工程，是一个完整的工程样板。
  • 内容与作品：可作为作品集展示；其数据与图表也能反哺写作/研报素材。

对目标用户（中文区加密散户 / 研究者）

  • 解决"打不开"：在大陆能直接访问并拉到数据，迈过信息获取的第一道门。
  • 一屏聚合：把行情/情绪/链上/衍生品/宏观五处信息压到一处，省去反复切换。
  • 给"状态"而非"买卖"：Nexus Score + 因子关系帮助判断"市场处在什么状态"，而非简单给信号。
  • 教育与练习：把抽象的"因子""相关性"可视化，帮助建立系统化思维；回测+模拟盘是无风险练习场。

但必须诚实说明边界：它不构成交易信号。数据深度与准确性（详见第二部分）不足以支撑实盘决策，更准确的定位是——"宏观温度计 + 情绪雷达 + 学习工具"，而非"决策系统"。把它当信号用会误导自己。

六、总结

三个最有价值的判断：

  • 真正的护城河只有一条：大陆可达性。数据、因子、图表都能被抄，但"在大陆能打开且免费"这件事，专业工具做不到、也不屑做。
  • 当前最大的短板是"可信度"而非"功能"。20 维里 2 维空转、宏观中枢靠人工、相关性样本短——这三点让那个 Nexus Score 看起来精致但经不起推敲。P0 三项修完，产品档次会明显上一个台阶。
  • 从"玩具"到"工具"的分水岭，是有没有历史因子库。一旦能回测"评分对未来的预测力"，它就从"看板"升级为"可验证的研究工具"。
