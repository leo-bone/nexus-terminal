# Nexus Terminal v3.22

加密货币 **实时监测 + 因子关系终端**。纯前端单页应用，无后端、无构建步骤。整站托管在 **Cloudflare**（前端 Workers Assets + 数据代理 Worker），并绑定自定义域名。

> **数据源全部经 Cloudflare Worker 代理**：浏览器只与 `nexus-api.uichain.org` 通信，由 Worker 从边缘节点抓取真实 API 并加 CORS 头。这样解决两件事——① 中国大陆无法直连 Binance/CoinGecko 等（Binance 在中国被封禁）；② 浏览器跨域（CORS）。**已实测从 Cloudflare 边缘可稳定拉取** Bybit / CoinLore / DefiLlama / blockchain.info / alternative.me / mempool.space / **bitcoin-data.com（BGeometrics，v3.10 新增：MVRV/活跃地址，免费档限速见 v3.10 章节）** / **Yahoo Finance** / NY Fed / U.S. Treasury / **Japan MOF（日本财务省）** / **Forex Factory**（Stooq 自 2026-10 起已实际失效，仅留作兜底）。Forex Factory 的 nfs CDN **会限流（429）**，故 `/api/calendar` 采用「成功长缓存 + 失败退避 + 陈旧兜底 + XML 降级」（详见 v3.6）。

> 部署形态：**纯 Cloudflare 单一出口**——前端（Workers Assets）+ 数据代理 Worker，均经 `workers_routes` 自动绑定到 `uichain.org`，无需手动配置 DNS。GitHub 仅作为**源码仓库**，不再对外提供 Pages 站点。
>
> - 前端（Cloudflare Worker + Assets / 自定义域名）：**https://nexus.uichain.org**
> - 数据代理 Worker（自定义域名）：**https://nexus-api.uichain.org**
> - 唯一对外入口：以上两个 `uichain.org` 子域（GitHub Pages 备用站已关停）
> - 源码仓库（仅存代码，不对外服务）：`https://github.com/leo-bone/nexus-terminal`

## v3.22 变更（本次）

**主题：让这台终端对自己负责。** v3.21 的结论是回顾性的、而且不好听——样本外保序反转、信号本身在衰减、建议仓位 0。这些数字如果只是躺在回放面板里，那它只是一份体检报告。本轮把其中两条变成**开着的监控**，并补上一台终端最该有却一直没有的东西：**改自己的卷**。

### ㉑ 预测台账 · 自我记分

这台终端每天都在出分，但从来没有人给它改过卷。现在把每天的「评分 + 当时价格」记进 `localStorage`，等 10 天过去再把真实收益填回去。

**为什么这是全套系统里最值钱的一块**：十年回放再怎么说都是事后，而台账是**唯一真正的前向测试**。代价是样本要靠时间攒，所以立了条硬规矩——**已结算样本不足 30 条就拒绝给结论**，只显示累积进度条。理由写在面板里：h=10 下 30 条记录折算有效样本只有 ~3 个非重叠窗口，低于这个量级任何「胜率 70%」都只是两三次巧合。

- 同一天反复刷新只覆盖不追加（幂等），回放游标模式下不记（否则会把历史日期混进来）
- 结算用**精确二项检验**判胜率是否优于抛硬币，不是正态近似
- 台账内部也做前半/后半 IC 对比，能回答「是不是在衰减」

### ㉒ 换手率与可执行性——⑲「建议仓位 0」的真凭实据

把评分落成仓位 `w = clamp((评分−50)/50, ±1)`，量出换手、成本、盈亏平衡换手率、评分自相关与符号翻转率。

**成本口径必须写明**：`SIZE_ROUNDTRIP` 是「0→1→0」一整趟的往返成本，所以每变动 |Δw| 单位付出的成本是 |Δw| × 往返成本/2。不写清这个，所有数字都对不上。

真实十年数据（3564 个交易日）：

| | 年化 | 夏普 |
|---|---|---|
| 毛（信号加的仓位） | +11.42% | 0.85 |
| 净（扣成本后） | +10.02% | 0.75 |
| **躺平买入持有** | **+68.89%** | **1.02** |

- 日均换手 0.0385，**盈亏平衡换手 0.313 → 实际只有它的 0.1 倍**；成本仅占毛收益 **12%**
- **于是真正的问题浮出来了：成本根本不是瓶颈。** 毛收益本身就跑不赢躺平（+11.4% vs +68.9%，夏普 0.85 vs 1.02）。⑲ 说「建议仓位 0」，原因在这里，**不在手续费**。在十年年化 +69% 的资产上，任何降低敞口的择时都要先跨过「少赚的涨幅」这道坎，IC 0.13 的强度远远不够。
- **日度命中率 51.9%，对照抛硬币的精确二项 p = 0.0292「显著」——但这个结论是假的。** 加了「躺平命中率」对照后：躺平命中率 52.0%，**边际命中 = −0.1 pp**。评分大部分时间偏多，所以「押对方向」里绝大多数日子其实是「多头仓 + 上涨日」，测的是**这个市场的上涨频率**，不是本终端的技能。在牛市里拿抛硬币当基准必然得出「显著优于随机」，那只是 beta。
- 评分自相关 lag1 **0.963**、lag20 0.723、符号翻转率仅 **4.9%**、平均连续同向 **20.3 天** —— 这是个**慢变量**，别用它做日度择时，那是把信号用在它不擅长的频率上。

### ㉓ 信号健康度——把 v3.21 的「信号在衰减」变成实时监控

最近 180 天的 IC 与**其余全部样本**的 IC 做 Fisher-z 两独立样本检验。对照组必须取「除最近段以外的全部」——用全样本当对照是错的，全样本包含最近段，两者不独立，方差公式不成立。

真实数据：**全样本 IC 0.134（t=2.52）→ 最近半年 IC −0.314（t=−1.33）**，对照段 0.145，z = −1.79，p = 0.074，**最近段滚动 IC 为正的比例 = 0%**。

这里踩了一个**必须记下来的错**：初版判定逻辑只要 z 没过 −1.96 就落到「健康」。于是「最近半年 IC 已翻负、滚动 IC 为正比例 0%」被贴上了**健康**的标签——**标签比证据强**，这是拿「没检出」冒充「没问题」。两条修正：

1. 新增 `flipwarn`（方向相反但未达显著）与 `weak`（滚动 IC 长期为负）两档；符号相反即使不显著也必须单独标出
2. **删掉「健康」这个词**，中性档改叫「与历史无显著差异」——它只说明没有证据表明变了，不等于证明还在工作

并补上**最小可检测效应 MDE**：最近段 n_eff 只有 18（180 天 / h=10），在这个样本量下最近段 IC 要跌破 **−0.355**（或涨过 +0.581）才会被判显著；实测 −0.314 **落在检测带之内**。**是这根尺子不够细，不是说这段没问题。** 没有这句披露，z 不显著一定会被读成安全。

### 本轮抓到的三个真 bug

1. **`binomPmf` 下溢**：`out[0] = exp(n·ln(1−p))`，n=3564、p=0.5 时是 `exp(−2470)`，直接下溢成 0；后面是乘法递推，**0 会传播到整个数组** ⇒ 双侧 p 恒等于 0。后果很坏：命中率 49.4%（正确 p≈0.19，完全不显著）被算成 **p=0.0000**，界面据此宣称「显著差于抛硬币」——一个纯数值 bug 被包装成了统计结论。修法：整段走对数空间，减最大值后再取指数。**n≤745 时旧写法碰巧不出错**，这正是它危险的地方：小样本测试全过，一上真实数据量就翻车。
2. **NaN 污染整块面板**：评分区列里混进一个 NaN（如末尾越界算出 `c[i+1]` 未定义），`Math.min(1, NaN)` 返回 NaN 并一路传播 ⇒ 换手率变 NaN ⇒ 面板静默失效。**`NaN == null` 为 false，`v == null` 的守卫拦不住它**，必须是 `!isFinite`。
3. **判定档位把「反向但不显著」标成「健康」**（见 ㉓）。

- 新增 **P 段 58 项断言 → 14 段 517 项全绿**（上轮 459）。P 段守的不是功能，是「不能把数值 bug 和功效不足包装成结论」：

## v3.21 变更

**主题：从「给分」到「给仓位」—— 补上中间那一段。**

前面十几个版本都在回答「现在几分」。但分数本身不可执行：没人能拿 57 分去下单。真正的缺口是中间那一段 ——

    分数 → 期望收益（校准） → 期望收益 → 仓位（风险化）

这一版补的就是这一段，外加一个前提检查：这 22 个因子到底有几个是真正独立的？

### 1. ⑰ 分位数组合检验

按评分**分位数**切 5 档，而不是固定阈值（>60 / <40）。原因很实在：固定阈值会出现「低分档只有几十个样本」，那几天的偶然走势就把整档平均收益带跑了 —— 分档口径一变结论就变，这种结论不结实。分位数切分保证每档样本量接近相等。

单调性用 **5! = 120 种排列全枚举**的**精确**置换检验。只有 5 个点时正态近似完全无用，但全枚举反而比蒙特卡洛更快也更准。

真实十年数据（h=10）：

| 档位 | n | 平均收益 | 胜率 | t（非重叠折算） |
|---|---|---|---|---|
| Q1 最低分 | 651 | −0.532% | 47% | −0.36 |
| Q2 | 661 | −0.015% | 48% | −0.01 |
| Q3 | 739 | +1.920% | 56% | 1.47 |
| Q4 | 723 | +3.699% | 61% | 2.45 |
| Q5 最高分 | 781 | +3.980% | 61% | 2.93 |

样本内 ρ = **1.000**，精确置换 p = **0.0083**，严格单调，Q5−Q1 = **+4.51%**。台阶漂亮得像教科书。

**然后我验了样本外，台阶整个塌了**：切分点只用前 60% 定死，后 1422 天评估 ——

| 档位 | Q1 | Q2 | Q3 | Q4 | Q5 |
|---|---|---|---|---|---|
| 样本外收益 | **+3.28%** | −0.04% | +1.61% | +2.32% | +1.07% |

ρ = **−0.259**，p = 0.658，**不单调**，Q5−Q1 = **−2.21%**（方向反过来）。

这时有一个容易犯的错：急着去改分档方式。所以我又往下追了一层 —— 把 IC 在前后两段各算一次：

| | IC | t | n |
|---|---|---|---|
| 前段 | 0.185 | 2.70 | 2133 |
| 后段 | **0.041** | 0.49 | 1422 |

**台阶塌掉只是表象，根本问题是信号本身在后段衰减到噪声区了。** 这时候任何「换个分档方式就能修好」的尝试都是在拟合噪声。这一条（前后段 IC 对比）不受分档口径影响，因此比台阶本身更值得相信 —— 面板上也是这么呈现的。

### 2. ⑱ 校准：一分到底值多少钱

IC 只告诉你排序对不对，不告诉你一分值多少收益，而仓位需要的是后者。OLS 拟合「收益 = a + b × 评分」，真实数据（h=10）：

- 每 10 分对应 **+1.935%**（10 日）
- **R² = 2.30%** —— 评分能解释的收益变异只有 2.3%，剩下 97.7% 是评分根本没看到的东西
- 斜率 **t = 9.15（重叠口径）→ 2.89（非重叠口径）**。3555 个 10 日窗口不等于 3555 个独立观测，按 n_eff = 355 折算后，一个「极其显著」变成「勉强显著」

**R² 才是决定仓位那一行。** IC 0.13 听起来「有信号」，换成 R² 就是 2% —— 这两个数字描述的是同一件事，但后者才决定能下多大注。

样本外（前 60% 拟合 / 后 1422 天评估）：**OOS R² = −8.63%**（负值，连「直接猜平均值」都不如），**OOS 校准斜率 = 0.045**（≈0，预测几乎不携带信息）。

**这一版还修掉一个我自己犯的方法论错误**：初版把「样本内校准斜率 = 1.031」当成「标定准确」的证据摆了出来。这是错的 —— 拟合值 ŷ 本来就是 y 在 x 张成空间上的投影，Cov(y,ŷ)/Var(ŷ) ≡ 1。样本内这个值**按构造恒等于 1，是个恒等式，不含任何信息**。已改为只报样本外，并在面板上写明为什么。

### 3. ⑲ 风险化仓位

五道约束取最紧的一个，并**指出是哪个在起作用**：

| 约束 | 真实数据上的值 |
|---|---|
| ⓪ 样本外闸门 | OOS R² = −8.63% ≤ 0 → **否决** |
| ① 成本门槛 | 超额需 ≥ 往返 0.2% |
| ② 波动率目标 | 0.15 / 0.43 = 34.9% |
| ③ Kelly 全额（超额 μ/σ²） | 评分 70 时 +572% |
| ④ 杠杆上限 | 100% |

**建议仓位 = 0%，起作用的约束是样本外闸门。** 诚实的解读写在面板上：**不是信号没用，是「量级」没用。** 校准映射出了样本连猜平均值都不如，而 Kelly 的输入就是 μ —— μ 不可信时 Kelly 的输出就是垃圾。

这一块还修掉一个会毁掉整个功能的错误：**初版把「总期望收益」喂给了 Kelly**，算出来 379%（评分 50）到 2099%（评分 95）。原因是我把这段样本的无条件漂移（10 日平均 +1.93%，牛市）也当成了信号 —— 那样算出来的答案恒为「牛市满仓加杠杆」，与信号强弱无关，毫无信息量。改成只用**超额部分 α = b × (评分 − 均值)** 之后，评分 50 的 Kelly 归零，这才对。

### 4. ⑳ 有效维度与分块因子

前提检查：22 个因子到底有几个真正独立？

| 指标 | 真实数据 |
|---|---|
| 参与率 PR = (Σλ)²/Σλ² | **9.79** |
| 熵有效维度 exp(H) | 13.03 |
| PC1 占比 | 21.5% |
| 解释 90% 需要 | 12 / 22 个方向 |

也就是说 22 个因子里真正独立的方向大约只有 10 个。**这直接解释了 v3.20 的一个结果：为什么换成岭回归动态权重并没有变好** —— 信息本来就集中在少数方向上，换更精细的组合方法不会凭空产生 alpha。想改善模型，方向是**找新的独立维度**，不是在现有维度里重新配权。

分块（默认 4 块，**如实标注为默认值不是数据给的**）后块内等权合成，IC **0.1445 vs 原模型 0.1338**（差 +0.011，在 ±0.01 边缘），块间平均 |ρ| 从 0.130 降到 0.089。

顺序正交化后的独有信息量（按当前 |权重×贡献| 降序依次正交化）：fng 100% · tx 97% · hr 96% · us10y 91% · dxy 90% … 而 mom 0% · tech 0% · jgb 6% · geo 6% —— 后者不是没用，是**它说的已经被排在前面的因子说过了**。这比 jackknife（只看删除效应）更严谨：正交化直接衡量冗余。

### 5. 顺带修掉的一个 v3.20 bug（聚类簇数）

写 ⑳ 的聚类时顺手发现了 v3.20 ⑬ 网络里的同一个 bug：簇数选取比的是「最近 k 次合并的**累计**高度差」，累计量随 k 单调增长 ⇒ **必然命中 k 的上限**。所以 v3.20 README 里写的「5 个数据驱动簇」是**上限给的，不是数据给的**。

已两处统一改用共享的 pickKFromHeights：比**单次**跳跃，并要求该跳跃占到整个高度跨度的 25% 才算断层；否则判定为「连续谱、无离散块」，落到事前定死的默认值（4）并如实标注。真实数据上最大单次跳跃只占跨度 11% —— **这批因子构成连续谱而非离散块**，这本身就是一条结论。

### 6. 测试段 O（新增 119 项断言 → 全量 459 项全绿）

与 N 段同源：验的是**数学与口径**，不是「功能没崩」。

1. olsFit 对着解析解验（y=3+2x 无噪声 ⇒ b=2、a=3、R²=1、sdResid=0；中心处标准误 = sdResid/√n）
2. 置换检验的**端点值可手算**：完美递增 ⇒ ρ=1、p=1/120；完美递减 ⇒ ρ=−1、p=1；permute5 恰好 120 种且互不重复
3. 校准的三件真事：斜率能恢复；**非重叠 t 必然比重叠 t 保守**；信号在后段消失时 ⇒ 样本内 R² 仍为正而**样本外必须塌掉**
4. 仓位：**五道闸门各自能单独把仓位打到 0**，且「起作用的是哪个」不能报错
5. 有效维度对着解析解验：单位特征值 ⇒ PR = 熵维度 = p；完全共线 ⇒ PR = 熵维度 = 1
6. 聚类：同块必须真的同簇（dxy-us10y 同簇、dxy-gold 不同簇）—— 比「簇数=2」更能证明聚类是对的

踩到的三个坑（都是测试写错的，不是实现错）：无噪声时 s2=0 导致标准误处处为 0，验「越远越宽」必须用有噪声的拟合；effectiveDim 收的是**特征值数组**不是矩阵，传矩阵会静默返回 null；FZ.ids 的顺序是 REPLAY_IDS 的顺序，不是合成数据里 ids 的顺序，按位置猜下标会验错对象。

## v3.20 变更


**主题：把三处「业余做法」换成机构做法 —— 动态权重的评分、可辩护的关系网络、允许漂移的相关性。**

动的是三个位置：综合多空评分的权重来源、因子关系网络的判定口径、相关性是否允许随时间变化。它们的共同点是：原来的做法都能跑出「看起来专业」的数字，但都经不起一句追问。

### 1. ⑫ 动态权重：增量式岭回归（walk-forward）

原来的 Nexus Score 是 `50 + 22 × Σ(w·dir·z)/Σw`，其中 `w` 是手写的工程判断 —— 它无法被检验。现在换成可以被检验的东西：

- **权重 = 对未来收益的预测系数**，由历史逐日滚动估计。22 个宏观因子彼此高度共线（美元 / 美债 / VIX 常常是同一件事的三个侧面），共线下 OLS 的系数会放大到荒谬量级，所以必须**岭回归**
- **无前视偏差**：第 t 天只能用「前向收益已在 t 日收盘揭晓」的样本。实现上，第 t 天新增的样本是 z(t−h) → r(t−h→t)，它的标签今天收盘才出现；加完样本才允许重估系数，再预测 t→t+h（未知）
- **增量累加器**（X'X / X'y 按样本累加，除以 n 后再加罚 ⇒ λ 不随训练样本量漂移）让每次重估只要 O(K³)，所以每 5 天重估一次也不掉帧：**十年 3565 天、676 次重估，实测 268ms**
- **λ 事前定死**（默认 1 ≈ 一个单位因子方差）。四条 λ 全部列出来是为了显示**结果对调参有多敏感**，而不是事后挑最好看的那条
- **两套口径**：全回放维（历史保真）与实时可用维（去掉 5 个没有实时数据源的回放专用因子，否则线上永远只能代入 z=0）

**真实数据上的结论**（十年回放，2017-07 → 2026-10，3376 天评价区间）：

| 口径 | IC(10日) | t | 多空差 |
|---|---|---|---|
| 手写权重（现状） | 0.136 | 2.49 | 4.05% |
| 岭回归 λ=1（默认口径） | 0.126 | 2.30 | 4.31% |
| 岭回归 λ=0.05（几乎不收缩） | 0.096 | 1.76 | 3.22% |
| 等权 z 合成（参照） | 0.136 | 2.49 | 3.92% |

**动态权重没有打赢手写权重**（IC 略低、多空差略高，差距都在 0.01 量级）。这是预期内的结果，也正是这块面板的意义：它现在能**把这件事证出来**，而不是继续靠主张。学到的方向与手写假设一致度 12/18（67%），不一致的那几个（例如原油被学成了正向）值得单独复核。

### 2. ⑫b 分歧度：没有离散度的点估计是不完整的

12 个因子加出 57 分，可能是「12 个都温和偏多」，也可能是「6 个狂热看多、6 个极度看空互相抵消」—— 两种情况的含义完全相反，前者可以照着做，后者说明模型内部在打架。新增：一致度（同向权重占比）、分歧 σ、**jackknife 敏感度**（逐个删掉一个因子重算，给出分数摆动区间并点名「谁在一个人说了算」）。标准误按「因子互相独立」计算，并明确标注为**不确定性的下界** —— ⑬ 已证明它们高度相关。

### 3. ⑬ 关系网络 v2

| 原来 | 现在 |
|---|---|
| pairwise 相关直接求逆 | 先做**谱截断保证半正定** + 向常数相关目标**收缩**（δ 直接显示在面板上）。不修正就求逆，会得到数值上「看着没问题」的荒谬偏相关 |
| 只给总相关 | 可切**偏相关**（精度矩阵）= 控制住其余全部因子后的**直接**关系 |
| 连边靠 \|r\|>0.08 | 连边由 **BH-FDR(q<0.05)** 决定，偏相关的自由度按 n−p 折算 |
| 只有阈值网络 | 可选 **MST**（Mantegna 距离 √(2(1−ρ))，n−1 条边的最强骨架） |
| 只有一张图 | 统计条：**吸收比 PC1 / PC1-2**、分散化比率、平均 \|ρ\|、数据驱动分簇、BTC 最强邻居 |

真实数据（120 日窗，15 条序列）：平均 \|ρ\|=0.188、PC1 吸收比 25%、DR=3.08、δ=0.17；105 对里只有 28 对通过 BH-FDR，其余**淡化显示但保留数值**（淡化 = 不确定，不等于零）。

> **v3.21 更正**：v3.20 这里原写「5 个数据驱动簇」，**该说法已被推翻**。簇数当时比的是「最近 k 次合并的**累计**高度差」，而累计量随 k 单调增长，必然命中 k 的上限 —— 那 5 个簇是**上限给的，不是数据给的**。已改为比**单次**跳跃，并要求该跳跃占到整个高度跨度的 25% 才算「断层」；真实序列上最大单次跳跃只占跨度 **11%**，说明这批序列是**连续谱而非离散块**，此时簇数落到事前定死的默认值并如实标注。两处聚类（⑬ 网络 / ⑳ 分块）现在共用同一个 pickKFromHeights，不会再出现两种「数据驱动的簇数」。

最有意思的一条实测：**DXY–BTC 总相关 −0.315，控制住其余因子后偏相关只剩 −0.080**。也就是说「美元涨、BTC 跌」这条常见说法，大部分是经由标普 / VIX / 黄金这一组风险偏好因子传导的，而不是美元对 BTC 的直接作用。这种区分正是总相关做不到的。

### 4. ⑭-⑯ 相关性是会漂移的

- **⑭ 领先-滞后扫描**：对每个因子试 −5…+5 共 11 个偏移。这一步天生是**事后的**（先试 11 次再挑最好的，全是噪声也会挑出一个「最优滞后」），所以配两道防线：全家族（序列数 × 11）一起做 BH-FDR；**样本劈成前后两半各自找最优滞后，两段不一致的一律不采信**。实测：标普与 BTC 同步 r=0.469（两段一致）；联邦基金利率领先 4 日 r=0.216、q=0.027（两段一致）；而 VIX 的 −0.405 被标为「前/后段不一致」—— 尽管它的 r 更大
- **⑮ 相关性突变**：短窗 vs 365 日窗在 Fisher-z 空间做差并标准化，\|z\|>2 表示关系变化超出抽样噪声能解释的范围。实测 DXY×USDJPY 0.60 vs 0.31（z=2.57）、BTC×黄金 0.43 vs 0.20（z=2.05）。这是**分散化假设的复核**，不是价格预测
- **⑯ 滚动系统性共振**：全部序列两两配对的滚动相关等权平均 + \|ρ\|>0.5 的占比（90 日窗）。它上升 = 因子开始一起动 = 多因子分散化在失效。当前 0.038（z=0.12，正常区间）

性能：整套（谱分解 + 153 对滚动相关 + 滞后扫描）在十年数据上约 650ms，按「最大日期」缓存 —— 日频数据一天才变一次，不会每次 60 秒刷新都重跑一遍。

### 5. 测试段 N（新增 102 项断言 → 全量 340 项全绿）

这一段的定位与前面不同：前面验证「功能没坏」，N 段验证**数学没错**，四组独立交叉验证：

1. 特征值 / 求逆 / 解方程对着**解析解**验（不变量 tr 与 ‖A‖²_F、A·A⁻¹=I、A·v=λ·v、三变量偏相关闭式解 ρ₁₃.₂=(r₁₃−r₁₂r₂₃)/√((1−r₁₂²)(1−r₂₃²))）
2. 岭回归系数与**测试里另写的一份 Gauss-Jordan 独立实现**逐位对照（22 维全部 <1e-8）—— 一次验掉累加器和 Cholesky 两处
3. **前视偏差零容忍**：篡改未来 60 天数据后，92 天的历史预测逐位不变
4. 偏相关的定性含义：共因子造成的虚假相关（corr(Y,Z)=0.931）必须在偏相关里掉下来（实测 0.328）

顺带修掉的两个真实缺陷：三角不等式必须在**自洽的**相关系数三元组上验（随手抽三个独立的 r 未必能构成合法相关矩阵，那样验是在冤枉 Mantegna 距离）；相关矩阵报告的谱必须是**最终那个矩阵**的谱（之前报的是夹紧前中间量的谱，于是「已半正定」这句话是空的）。

## v3.19 变更

起因是一条用户提问：`👷 非农就业 +0.6 利多 · 预期 89K（未发布·半权重） —— 这个是什么意思？`

追下去发现三个真实缺陷，都不是算法问题，是**数据时效性**问题。

### 1. XML 降级路径把发布钟点丢了

数据源有两个出口：JSON 端点带完整 ISO（`2026-10-02T08:30:00-04:00`），XML 端点则是 `<date>` + `<time>` 两个字段。解析函数只取了 `<date>` —— 于是**一旦 JSON 端点 429 降级到 XML，发布时刻就被整个丢掉**，前端拿到 `10-02-2026`，无从判断「还没到点」还是「该发了数据没来」。

修复分了两步，第二步是一次**被交叉验证推翻的自我纠错**。

**第一步**：`ffXmlTimeToIso()` 补取 `<time>` 字段，合成完整 ISO。

**第二步（纠错）**：我最初假定 FF 的 `<time>` 是美东时间，于是用 `Intl.DateTimeFormat` 解析 `America/New_York` 的夏令时偏移。这段代码看起来相当严谨——直到把同一个事件摆到两个端点上一比对，立刻露馅：

| JSON 端点（自带时区） | XML 端点（`<date>` + `<time>`） |
|---|---|
| `2026-09-28T08:15:00-04:00` | `09-28-2026 12:15pm` |
| `2026-09-28T13:30:00-04:00` | `09-28-2026  5:30pm` |
| `2026-09-29T10:00:00-04:00` | `09-29-2026  2:00pm` |

左边折成 UTC，正好等于右边钟点 —— **XML 的 `<time>` 本来就是 UTC**。多做那一次美东换算，等于把发布时刻推晚 4 小时，会让「已过时辰」报警迟到整整一下午。已彻底移除换算逻辑，并把上表三条实测对齐固化成断言（M 段）。

> 教训：**由假设驱动的「严谨」比偷懒更危险**。写夏令时换算时我确信自己在做正确的事；而交叉验证只花了三十秒就推翻了它。凡是「应该是这样」的推断，都要找个独立出口对一遍。

### 2. 30 分钟退避在发布窗口太长

> 更正一处先前的误判：此前以为 `CAL_TTL=21600`（6 小时）阻塞了刷新。实际地，**边缘缓存的新鲜度由 `CAL_MIN_RETRY=1800`（30 分钟）控制**，`CAL_TTL` 只是 HTTP 头。所以那次非农滞后 3 小时确实是数据源未回填，不是缓存的锅。

但 30 分钟本身仍然太长——非农/CPI 发布后 BTC 常在数分钟内反应。现在重大事件（非农/失业率/CPI/核心PCE/联邦基金利率/初请）在发布时刻 **±2 小时内，退避压到 5 分钟**。

**开发过程中被测出来的一个bug**（值得记住）：`(t - now)` 是毫秒，却直接和以秒计的 `BIG_WINDOW_SEC=7200` 比较 —— 窗口实际变成 **7.2 秒**，功能静默失效。单元测试抓出来的：所有「应该命中热点」的断言全部 FAIL。

### 3. 「未发布」被当成万能借口

发布时刻过去 60 分钟仍没有实际值，界面依然显示「未发布·半权重」，使用者会以为「还没到」。现在改为：

| 情况 | 显示 |
|---|---|
| 还没到发布时间 | `预期 89K（未发布·半权重）` —— 正常预告 |
| **过了发布时间 + 60min 仍无值** | `预期 89K（已过时辰·数据未到）`，**卡片转灰，标「数据未到」** |
| 有实际值 | `实际 150K / 预期 89K`，全权重 |

### 4. 下周的预告会盖掉本周的真值

`econFind` 原先纯倒序取最后一条匹配项。当同一标题同时存在「本周已发布（有 actual）」和「下周预告（无 actual）」时，**未来预告会盖掉真实 surprise** —— 等于白白丢掉最有价值的那次数据。改为优先取「最近一条已发布」，没有才退回「最近的待发布」。

### 慎重的取舍

陈旧态**没有**把因子剔出评分，也**没有**对 z 额外打折。理由是：此时失效的是「我不知道实际值」，但「市场预期从 162K 降到 89K」这个信息本身仍然有效、仍然反映共识。真正要防的是**把它当事实看**——所以用视觉降级（灰标）而非数值阉割来解决。

### 测试

新增 **M 段 38 项**断言，共 **12 段 238 项全部通过**。覆盖：宽限期边界（30min 不报 / 90min 报）、旧无钟点格式不误伤、真值路径不被预告覆盖、渲染含 stale 分支、热点窗口单位换算、**Worker 代码是从 `worker.js` 原样抽出后跑的**（不手抄，避免测试与实现脱节）、夏令时/冬令时/跨午夜时区换算。

## v3.18 变更

**主题：产品自带证伪装置 —— PBO 回测过拟合概率、去通胀夏普 DSR、买入持有基准、零信息对照。**

一句话总结：**本产品现在能自己证明「它有信息」，同时也能自己证明「这部分信息不足以转化为超额收益」。**
这两件事由同一套代码给出，不依赖任何外部信任。

### 1) 为什么必须有这一版

v3.17 补上了多重检验校正（16 个「显著」里只有 2 个扛得住 Bonferroni）。但它回答的是
**「这次检验本身可不可信」**，还剩一个更尖锐的问题没碰：

> 就算因子真的含有信息，**把它变成策略之后，值不值得用？**

绝大多数因子产品的做法是：算出一个漂亮的策略夏普，然后展示它。本版做的正好相反 ——
先承认可能存在自欺，再把自欺的程度量化出来摆在同一个页面上。

### 2) 新增：⑪ 回测过拟合概率（PBO / CSCV）与去通胀夏普（DSR）

采用 Bailey & López de Prado 的两项工作：

| 方法 | 出处 | 回答的问题 |
|---|---|---|
| **PBO (CSCV)** | Bailey & López de Prado 2017, *The Probability of Backtest Overfitting* | 「挑选配置」这个动作本身带来了多少过拟合 |
| **DSR** | Bailey & López de Prado 2014, *The Deflated Sharpe Ratio* | 最终那个配置的夏普里，有多少可以被「试了很多次」解释 |

**PBO 的做法（枚举全部组合，不是抽样）**

1. 构造 N=12 个候选配置（同一批因子的不同粒度子集：Top1 / Top2 / … / Top12 / 全因子 / 奇偶分组）
2. 把 3525 个有效交易日切成 S=10 个互不重叠的块
3. 枚举全部 **C(10,5) = 252 种**「一半训练 / 一半测试」的划分
4. 每种划分只在训练集里挑最优，再回到测试集看它排第几 → λ = logit(排名)
5. PBO = P(λ ≤ 0)

> **工程要点**：朴素实现是 O(C(S,S/2)·N·T)，不可行。先把每个候选在每个块上的收益
> 一阶/二阶矩预累加，之后每种划分只剩 O(N) —— 这样才敢**枚举全部 252 种**而不抽样，
> 结论不依赖抽样运气。实测整套在浏览器里约 **0.6 秒**。

**DSR 的做法**

```
SR₀ = √V · [ (1−γ)·Φ⁻¹(1−1/N) + γ·Φ⁻¹(1−1/(N·e)) ]     γ = 0.5772 (欧拉常数)
DSR = Φ[ (SR̂ − SR₀)·√(T−1) / √(1 − γ₃·SR̂ + (γ₄−1)/4·SR̂²) ]
```

全部使用**单周期（日）口径**计算、报告时再年化，避免尺度串味。
已做偏度 γ₃、峰度 γ₄ 校正（本次 γ₄≈15，厚尾很重 —— 不做这一步会严重高估显著性）。

### 3) 三件「别的分析不会给你看」的东西

这部分是 v3.18 的核心价值，也是本产品敢于自称严谨的原因：

**① 买入持有基准（BH Benchmark）**

DSR 只会告诉你「能不能赚钱」。真正的机会成本是「**能不能赢过躺着不动**」。
本版把 `PSR(SR > BH)` 单列一行——**这是 Commonwealth 才配被称为「有没有用」的指标**，
而上一步（统计显著性）和这一步（有没有用）之间隔着一整个 BH 基准。

**② 系统性敞口检验**

计算最优配置的**平均仓位**（本次 = −0.0039，接近 0），确认它不是靠长期做多蹭上涨，
并额外给出**多空中性化后**的夏普（逐日扣掉当时已知的平均敞口）。

**③ 零信息对照（内置证伪装置）—— 最该读的一栏**

把同样的 12 个候选、同样的滚动窗口、同样的「挑最优」流程，喂进**与未来毫无关系**的
伪数据里重跑 10 次，看这台机器空转时能吐出多好看的数字。

伪数据用**循环移位**生成而非简单打乱：
`factor'[i] = factor[start + ((i − start + k) mod L)]`
一条序列循环移位后，它自己的边际分布、波动率、自相关**全部原样保留**，
只是起点变了——与未来收益的时序对齐被切断，而任何单序列统计量都看不出区别。
（简单打乱会顺手毁掉自相关，制造出偏乐观的假阴性。）

### 4) 实测结论（2026-10-02，BTC 日线 2016-12→2026-10）

| 指标 | 数值 | 读数 |
|---|---|---|
| 最优配置 | Top8 | 22 个因子里 IC 最强的 8 个 |
| 最优年化夏普 | **1.018** | — |
| 买入持有夏普 | **1.020** | 12 个候选里 **0 个**跑赢它 |
| PBO（经验） | **50.0%** | 训练选出的最优，到测试集排中位之后 |
| DSR | **96.5%** | 扣掉运气后夏普仍显著为正 |
| PSR(SR > BH) | **49.7%** | **几乎是抛硬币** |
| 零信息对照中位 / 最高 | 0.18 / **0.84** | 同一台机器在伪数据上能挑出来的水平 |
| 真实值在零信息分布的分位 | **第 100 分位** | 10 次伪数据运行**没有一次**追上真实值 |

**三个数字互不矛盾，合起来才是完整结论：**

1. **确实有真实信息** —— 真实 SR 排在零信息分布第 100 分位；与 v3.17 的
   White Reality Check 家族 p=0.005 互相印证：多高维噪声里确实藏着一点真东西。
2. **但「选配置」没有信息** —— PBO=50%，意味着挑哪个子集到样本外完全可以随机，
   Top8 只是恰好被挑中的那一个。
3. **且打不过躺着不动** —— 0/12 跑赢 BH，PSR(SR>BH)=49.7%。

一句话：**有 alpha 信号，但没有足以支付交易摩擦、超过被动持有的 alpha。**
这个结论不漂亮，但它比任何「策略年化 XX%」的宣传更接近事实，
也直接决定了这套东西现在**不应该被用来直接下单**，而应当作为对市场状态的**描述**。

## v3.17 变更

**主题：多重检验与过拟合校正 —— 补上「业余因子挖掘」与「专业机构」之间最硬的那条分界线。**

### 1) 起因：一道可以被量化的墙

过去十几个版本，本面板的判定一直是这样：给每个因子算 IC 与 t，凡是 `|t| > 2` 就标「有效」。这听起来天经地义，但把数字摆出来就不那么确定了：

- 一次回放要做 **22 个因子 × 4 个 horizon = 88 次**显著性检验
- 单个检验的 α = 0.05
- 即使 **88 个全是纯噪声**，统计上也期望出现 `88 × 0.05 = 4.4` 个「显著」

**「显著」是可以靠「试得够多」批量生产出来的。** 这是业余因子挖掘与专业机构最本质的差距之一，也正是 López de Prado 那套方法诞生的原因。v3.17 就是来补这一课——它不会让信号变强，只会告诉你**看到的信号里有多少能用「试得够多」来解释**。

### 2) 落地四种口径，真实回放的结果

数据窗口 2016-12-29 → 2026-10-02，3565 个交易日：

| 口径 | 门槛 | 通过 | 回答什么问题 |
|---|---|---|---|
| 未校正（α=0.05） | `\|t\| > 1.96` | **16 / 88** | 逐个看有没有信号 |
| Bonferroni | `\|t\| > 3.45` | **2 / 88** | 有没有任何一个能单独拿来用 |
| Šidák | `\|t\| > 3.44` | 2 / 88 | 同上，略宽松 |
| Benjamini-Hochberg FDR | `q < 0.05` | 2 / 88 | 显著结果里假发现占多少 |
| White's Reality Check | 家族 p | **0.005** | 整批里到底有没有真东西 |

- **16 个「显著」里 14 个扛不住 Bonferroni**（日债10Y / 美元指数 / 动量 / 技术面 / 美联储2Y / 黄金…）——它们是多重检验谬误的产物，不是 alpha
- 幸存的只有两个，且都在 **h=1（次日）**：MVRV 估值（IC −0.100，t −3.76）与技术面（IC 0.059，t 3.50）。注意 IC 只有 0.06~0.10 量级——**统计上站得住 ≠ 能用它赚钱**
- WRC：观测最优 |IC| = 0.155，而**纯噪声的中位数就有 0.047、95 分位 0.088**，家族 p = 0.005

### 3) 两个结论同时成立，而且并不矛盾

这是本块最想传达的一点：

- **家族检验显著** ⇒ 这批因子不是纯噪声，里面有真东西
- **逐个检验几乎全部失败** ⇒ 但没有任何单个因子的证据强到可以独立使用

两者同时成立描述的是同一件事：**信号真实存在，但薄而分散**。这正好对应 IC 只有 0.10 量级的现实——不是没有 alpha，而是 alpha 薄到必须用组合去承接，无法靠押注单个因子。这也是为什么「找一个最强因子」这条路本身就有结构性缺陷。

### 4) 对照组：纯噪声长什么样

回归测试 K 段构造了完全随机的数据（3 因子 × 400 天，零真实信息）：

- 纯噪声下，「这批因子里最好的那个」|IC| 中位数就有 **0.064**
- 也就是说，一个被孤立报道的「最佳因子 IC = 0.07」，本身**就落在随机可以达到的范围内**

市面上「某指标 IC 0.15 / 胜率 80%」这类宣传，绝大多数从未做过这一步。

### 5) 工程：7.6 秒 → 1.0 秒，且拒绝用偷懒换速度

WRC 的 bootstrap 朴素实现是 `O(B·K·m·log m)`（200 次重采样 × 22 因子 × 3555 点），实测 **7.6 秒**——在单线程浏览器里会直接冻住页面。三处优化：

1. **秩等变性**：打乱收益序列后，其秩只是被同一个排列作用，不必重新排序 → `O(m log m)` 降为 `O(m)`
2. **Σcs = 0 的性质**：因子侧已预中心化，故 `Σcs·(y − ȳ) = Σcs·y`，两次遍历并成一次
3. **全覆盖因子的快路径**：因子在整条日历上都有值时 `pos[q] === q`，省掉一层间接寻址

合计 **7.6s → 1.0s（约 7 倍）**，统计结论一字未变（家族 p 仍是 0.0050）。

> 踩过一个值得记的坑：中途试过把日历按每 3 点取 1 来提速，速度确实快了，但**家族 p 从 0.003 变成 0.060，结论直接翻转**。降采样会让样本量变小、抽样方差变大，人为把零分布撑宽——**用性能调整去改变统计结论是不可接受的**，已彻底移除，并在代码注释里写明了原因。

bootstrap 仍属重计算，故改为**异步执行**：首屏渲染完毕、显示「正在计算」，算完只刷新 ⑩ 这一块（`scheduleMt` / `renderMtBox`），回放不会被卡住。

### 6) 测试

回归测试新增 **K 段（21 项断言）**：数值核自洽（`normInv(normCdf)` 往返、`t→p` 换算、边界不返回 NaN）、合成纯噪声样本上的关系式（`Bonferroni 通过数 ≤ 未校正通过数`、`BH ≥ Bonferroni`、`q 值 ≥ p 值`）、WRC 输出合理性、`renderMtBox` 在无数据与「计算中」两种状态下均不抛错。**10 段 161 项断言全部通过、0 失败。**

- 两个信号**仅用历史数据、严格因果、无前视偏差**：
  - **体制 wild**：20 日年化已实现波动率（`√方差 × √365`）≥ 0.80 —— 与线上 `currentRegime()` / 回放 `realizedVol()` 完全同口径
  - **DVOL 恐慌**：近 365 日窗口内当前值百分位 ≥ 0.90 **或** 60 日 z ≥ 2 —— 与 `/api/dvol` 同口径；需 ≥120 日 DVOL 历史才开始计算（故该信号可用始于 **2022-05-09**）
- 数据：BTC 日线 `/api/history`（**2014-09-17 → 2026-10-02，n=4399**）+ DVOL 序列（**2021-03-24 → 2026-10-02，n=2024**）
- 两类检验：
  - **A 预测力**：警报触发 vs 未触发时的远期（5/10/20 日）BTC 收益差 + Welch t 值
  - **B 防御回测**：警报触发次日空仓 vs 一直持有，比**总收益 / 最大回撤 / 夏普 / 在市率**（因果：用前一日收盘已知的信号决定次日仓位）

### 2) 结论：警报不是机械减仓开关（反直觉，但要看数据）

| 信号 | 触发天数 | 触发后 10 日收益（vs 未触发） | t | 防御 vs 基准：夏普 | 防御 vs 基准：最大回撤 |
|---|---|---|---|---|---|
| wild 仅 | 807 | **+3.28%** vs +1.53% | **+3.24** | 0.82 → **0.64**（更差） | −83.4% → −70.6%（降了，但代价是收益腰斩 +18883%→+2346%） |
| DVOL 恐慌仅 | 172 | +1.35% vs +1.87%（20 日 **+0.59% vs +3.99%**） | −0.89（20日 **−4.56**） | 0.82 → **0.77**（更差） | −83.4% → **−83.4%（完全没降）** |
| either（任一触发） | 947 | +3.04% vs +1.52% | +3.17 | 0.82 → **0.59**（更差） | −83.4% → −72.3% |
| **combo 双重警报** | **32** | **−0.24%** vs +1.86%（差 −2.11%） | **−2.41** | 0.82 → 0.81（几乎无差） | 无变化（太稀疏） |

三条诚实结论：

1. **wild 体制是动量信号，不是危险信号。** 波动率飙升时 BTC 未来 10/20 日收益反而显著更高（+3.28%/+7.01% vs +1.53%/+3.14%，t=+3.24/+4.53）。这符合 crypto 特性：牛市主升浪本身就是高波动。所以**「一进极端体制就空仓」会系统性错失涨幅**，夏普从 0.82 掉到 0.64。
2. **DVOL 恐慌日空仓并不能降低最大回撤。** 恐慌信号在 20 日远端确有前瞻性（20 日收益差 −3.40%，t=−4.56），但历史上那次 −83.4% 的最大回撤并不发生在这些恐慌日，因此精准躲开恐慌日 MDD 纹丝不动，夏普反而因踏空下降（0.82→0.77）。
3. **唯一有统计意义的是「双重警报」的短周期预警。** wild 与 DVOL 恐慌同时触发（仅 32 天、占时长 0.7%）时，未来 10 日均值 −0.24%、显著低于未触发的 +1.86%（差 −2.11%，t=−2.41）。它是真实的前沿预警，但**太稀疏，不足以支撑系统化交易**（期内几乎不改变组合结果）。

### 3) 定位收敛：行为护栏，不是机械卖出信号

- 面板回放 ⑧ 块新增「**护栏实证（v3.15 walk-forward 回测）**」结论注，把上述三条直接写进产品——用户不必翻代码就知道「这条警报该信到什么程度」

- **因子动态可用性闸门（FACTOR_DEP）**：每个因子按自己的可见长度决定进不进分母，缺序列 `ok:false`、不稀释评分。阈值用「z 算法硬门槛」口径（rollZ→60 / chgZ→80 / 长窗→110），不是「窗口填满」——后者会静默剔除实时模式下的短序列源
- **预计算 z 表（性能）**：回放是按时间顺序推进的，z 只依赖自身序列前缀 → 一次 O(n) 预计算、回放 O(1) 查表。实测 **4387ms → 522ms**
- **一个隐蔽的数值稳定性杀手**：120 点全同值窗口（EFFR/日债利率平台期）真实方差为 0，但原 `rollZ` 用 `sqrt(sum((x-mean)²)/n)` 得 sd≈3.5e-15 而非 0 → z = **−1**（纯浮点噪声决定的符号）；滑窗版因大数相消走 `|| 1` 兜底 → z≈0。**同一天同一序列，两种算法差整整 1.0**。解法：每步精确重算窗口、保持与原实现相同的求和顺序，回归测试断言逐位相等（实测偏差 `0.00e+0`）

## v3.8 变更（上一版）

**主题：从玩具到工具的分水岭 —— 终端第一次能自证有没有用。** 新增「评分历史与有效性检验」：把 2 年的长历史序列取回来，用与实时**完全相同**的因子代码逐日重放出历史 Nexus Score，再检验它与「未来 1/5/10/20 日 BTC 收益」是否真的相关。

### 0) 架构决策：无数据库的历史回放

回放不需要 KV / D1 / cron。Nexus Score 的每个输入本身就是历史序列 → 只要把长历史发给前端，就能用**同一套因子代码**逐日重放。这避开了「双份实现」的经典陷阱（回放逻辑与实时逻辑脱节）——回放用的就是实时的 `computeNexusScore`。

核心机制是 **asof 游标**：`state.asof = { DXY: 123, ... }` 表示每条序列只看到该下标之前的数据（`asofCut()` 统一实现），`state.asof === null` 即实时模式。回归测试用「**篡改未来 60 天的输入，历史评分必须一字不变**」硬验证无前视偏差。

### 3) IC 检验 + 显著性折算（方法论要点）

- **Spearman（秩相关，主力）+ Pearson**；前向 1/5/10/20 日 BTC 收益
- 分档（<40 / 40~60 / >60）平均收益 + 胜率，基准 = 全样本前向收益均值
- **重叠窗口折算**：前向 h 日的相邻样本高度重叠 → n 不是有效样本量。`neff = n/h`，`SE ≈ 1/√neff`，`t = IC/SE`，星标 `*` = |t|>2、`**` = |t|>3。**不做这一步会把纯噪声读成显著信号** —— 这是因子研究最常见的自欺

### 4) 诚实结论：17 维子集当前 IC ≈ 0

448 个交易日的真实数据实测：

```
IC(10日) Spearman = -0.012 · Pearson = -0.000（无星标）
分档样本 82 / 294 / 82，10 日平均收益 -1.00% / -0.32% / -0.84%（不单调）
偏多档（>60）胜率 34%，反而低于偏空档的 48%
```

## v3.7 变更（上一版）

**主题：这次不是加功能，而是「把假的变成真的」。** 用真实浏览器（CDP 无头 Chrome）对线上站点做了端到端渲染检查，抓到 **1 个掩盖真问题的诊断缺陷 + 1 个持续失效的数据源 + 1 个会系统性扭曲评分的隐性偏差**，全部修复。

### 1) `getJSON` 的 `throw 0` —— 掩盖一切的诊断黑洞

```js
if (!r.ok) throw 0;        // 旧：HTTP 402 / 429 / 500 / 404 全部变成一个 "0"
```

浏览器控制台只会打出 `global fail 0`，**无法区分是限流、接口挂了、还是参数错了**。正是这个黑洞让 v3.6 的日历 429 排查变得绕。现改为 `throw new Error('HTTP ' + r.status)`，任何上游异常都能直接读出状态码。

### 2) CoinPaprika 全局接口持续 402 —— BTC占比因子长期死的真凶

全量探测 15 个上游数据源后发现：

| 源 | 状态 |
|---|---|
| coinpaprika `/v1/global`（主源） | ❌ **HTTP 402 Payment Required**（免费档 60 次/时，超限封 1 小时） |
| coingecko `/v3/global`（白名单里标了「备用」） | ❌ HTTP 429 —— **而且前端根本没写兜底逻辑，这个「备用」是死的** |
| **coinlore `/api/global/`** | ✅ 200，**免费、无 key、限额宽松** |
| mempool.space `/mining/hashrate/1y` | ⚠️ 偶发 404 / 21 秒超时（瞬时限流） |
| 其余（Bybit / llama / blockchain.info / Yahoo / MOF / alternative.me） | ✅ 200 |

**实际后果**（线上截图确认）：`BTC占比` 显示的是一个**硬编码的假值 52.0%**（真实 58.4%，差 6.4 个百分点），`稳定币占比` 和 `算力趋势` 显示「—」，链上面板的**总市值 / BTC占比** 整格空白 —— 而界面看起来一切正常。

**修复**：Worker 新增 **`/api/global`**，与 `/api/calendar` 同一套模式：**coinlore（主）→ coinpaprika（备）→ coingecko（备2）三级兜底 + 成功缓存 10 分钟 + 失败退避 5 分钟 + 陈旧兜底**，响应头暴露 `X-Global-Source: coinlore / edge-cache / stale`。

> **口径坑**：不同源的 BTC 占比算法不同 —— coinlore 给 58.4%，coinpaprika 通常给 55% 左右，**系统性差 3~5 个百分点**。切换主源必须同步校准因子里枢（52 → 56），否则 z 会整体漂移。

### 3) 「无数据因子稀释评分」—— 一个此前没人发现的评分偏差

旧逻辑里，只要 `dir != 0`，因子就进加权平均的**分母** —— 哪怕它根本没有数据（z=0、贡献 0）。这意味着：

> **每个死掉的数据源都在把 Nexus Score 往 50（中性）拉。** 三个死因子 = 1.7 假权重 / 19.9 总权重 ≈ 8.5% 的评分被硬编码的零稀释。数据源挂得越多，终端越「看起来中性」，**故障被伪装成了「市场没有信号」**。

修复：因子返回 `{ ok: false }` 时**退出分母**，`nDead` 计数并在面板标题显示「N 无数据」。回归测试 F 段验证：活因子全部贡献 +2 时评分必须等于 94（旧逻辑会算成 91）。

### 4) 算力端点容错

mempool.space 的 `/mining/hashrate/1y` 偶发 404/超时（瞬时限流），一次失败就让算力因子整轮空转。现改为失败后 1.2 秒重试一次，并记录真实错误信息。

### 5) 验证方式升级：从 vm 沙箱到真实浏览器

此前所有测试都在 vm 沙箱里跑 —— 能验证逻辑，但**验证不了「浏览器里 DOM 到底渲染成了什么」**。本次用 CDP（Chrome DevTools Protocol，Node 22 内置 WebSocket，零依赖）驱动真实无头 Chrome 打开线上站点，注入探针读取真实 DOM：

| 检查项 | 修复前 | 修复后 |
|---|---|---|
| `👑 BTC占比` | 中性 · **52.0%（假值）** | 利空 · **58.4%（真实）** |
| `🪙 稳定币占比` | 中性 · — | 中性 · 10.9% · 场外购买力 |
| `⛏ 算力趋势` | 中性 · — | 利多 · 近90日加速 |

## v3.6 变更（上一版）

**主题：给因子加上「方向」，并补上日元这条最贴近加密的宏观线。**

### 1) 修复 Nexus Score 的「方向混用」（最重要的逻辑缺陷）

原实现把所有因子的**原始 z 直接加权相加**。但因子本身的方向是**混的**：美元指数、美债收益率、VIX、日债收益率上涨对加密是**利空**，而标普、算力、链上活跃上涨是**利多** —— 直接相加等于把利空项当利多计入，评分方向是乱的。

实测：把美元指数 z 拉高 → 旧评分**上升**（把它当成了利多），这显然是错的。

现在每个因子显式声明 `dir`：

- `dir = +1` → z 越高越「利多」
- `dir = -1` → z 越高越「利空」
- `dir =  0` → 只展示、不参与评分

合成公式改为 **Nexus Score = 50 + 22 × Σ(w · dir · z) / Σw**。

### 2) 新增 2 个日元因子（用户要求的「日元利率」）

| 因子 | 数据源 | 当前实测 | 方向 |
|---|---|---|---|
| 💴 **美元/日元** | Yahoo Finance `JPY=X`（日频，1 年） | **158.23** | **+1** |
| 🇯🇵 **日债 10Y** | **日本财务省** 国债金利情报 CSV（日频，**900 个交易日 ≈ 3.5 年**） | **3.057%** | **−1** |

**为什么日元比黄金更贴近加密**：2024-08-05 的全球风险资产暴跌（含加密）就是**日元套息交易平仓**引发的 —— 日元急升 → 套息头寸被迫平仓 → 抛售一切风险资产换回日元。所以：

- 美元/日元**上行**（日元贬值）= 套息顺畅 = 风险偏好 → `dir=+1`
- 日债收益率**上行** = 套息成本抬升 / 日本资金回流 = 平仓压力 → `dir=−1`

### 3) 趋势型序列改用「变化率 z」（chgZ），修复长期贴顶

黄金 / 标普500 / 原油 / 算力 / 美元日元 / 日债10Y 这些序列是**长期单调上行**的。直接对「水位」做滚动 z-score，末值永远在区间顶部 → **z 恒为 +1.5~+2.5，长期贴顶**，因子等于空转。

改为对「近 N 期的相对变化」做 z-score（衡量「涨/跌得是否异常快」）：

- 回归测试实测：一条**稳定复利上涨**的序列，`chgZ ≈ 0.40`（合理地接近 0），而旧的 `rollZ ≈ +2.5`（贴顶）—— 这组对照被写进了 `tests/regression.js` 的 E 段。

### 4) 美联储因子改用美债 2Y（替代 EFFR 水平）

EFFR 是**阶梯常数**（调息后几个月不动），120 日滚动 z 恒为 0，等于空转。改用 **美债 2Y 收益率**（市场对美联储政策路径的实时定价），日频有波动、信息量大。EFFR 仍保留在宏观面板作为「当前政策利率」展示。

### 5) 修复几个真实缺陷

| 缺陷 | 说明 |
|---|---|
| **因子网络动画循环泄漏** | `refreshAll` 每 60 秒调用一次 `initNetwork()`，而它每次都启动一个新的 `requestAnimationFrame` 无限循环 —— **每刷新一次泄漏一个循环**，跑一小时就有 60 个循环同时重绘同一块画布。现加全局单例开关，并在力导向收敛后**自动停帧省电**（刷新/缩放时重新启动）。 |
| **回测净值图尺寸错** | 原在 `.btres` 面板 `display:none` 时就绘制画布，`clientWidth = 0` 退化成 320px，面板展开后被**拉伸变形/发虚**。现先展开面板再绘制，并按 `devicePixelRatio` 高清渲染。 |
| **模拟盘静默失败** | 账户是懒加载的，若在首轮刷新完成前点「开仓」，`state.acct` 为 null 会**静默 return**（无任何提示）。现改为 `bindUI()` 阶段就初始化账户。 |
| **宏观快照超时过短** | 客户端拉 `/api/snapshot` 的超时只有 9 秒，而该端点冷启动（聚合 15 条序列 + 1.2MB 日本国债历史文件）常需 10~30 秒 → 偶发静默失败、宏观全部显示「—」。现提到 25 秒（经济日历 20 秒），并把快照边缘缓存延长到 15 分钟。 |
| **热力图列头重名** | 20 个节点下，`US10Y / UST2Y / USDJPY` 截断后都是 `US`。现在为每个因子配了唯一短标签（`10Y / 2Y / 日元`）并加 `title` 提示。 |
| **经济日历被限流后「锁死」** | Forex Factory 的 nfs CDN 对高频请求返回 **429（Rate Limited 的 HTML 页）**。原实现只在成功时缓存 15 分钟、失败即返回 502，一旦被限流就会**每次请求都再去打 FF** → 持续 429，5 个事件因子全部落中性（实测复现）。现改为「成功缓存 6 小时 + **失败退避 30 分钟**（退避期内直接吃缓存）+ **陈旧兜底**（失败返回上一份可用数据而非 502）+ **XML 端点自动降级**」，并在响应头暴露 `X-Calendar-Source: live / edge-cache / stale`。 |

### 6) 日元数据源是怎么找到的（实测记录）

| 候选 | 结果 |
|---|---|
| Yahoo `JPY=X`（美元/日元） | ✅ 200 |
| Yahoo `6J=F`（日元期货）/ `^N225` | ✅ 200（未采用，USD/JPY 更直接） |
| Stooq `usdjpy` | ❌ 返回 JS 反爬验证页 |
| 日本财务省 `…/interest_rate/jgbcm.csv` | ✅ 200（**仅当月**） |
| 日本财务省 `…/interest_rate/data/jgbcm_all.csv` | ✅ 200（**1974 至今全历史**，1.17MB） |
| BOJ 政策利率 / DBnomics 日本长端利率 | ❌ 未取到连续日频序列 |

> **编码坑**：财务省 CSV 是 **Shift-JIS**，而 Cloudflare Workers 的 `TextDecoder` **不支持** shift_jis（只支持 utf-8 / utf-16 / windows-1252）。好在**除表头外的数据行全是纯 ASCII**（日期形如 `R8.8.31` + 数字），所以 Worker 里按 UTF-8 读入后**只解析 ASCII 数据行**即可绕开编码问题。列序号固定：`cells[0]=日期，cells[10]=10年`；日本年号换算 `R(令和)=2018+N / H(平成)=1988+N / S(昭和)=1925+N`。
> 大文件（1.2MB）单独做 **6 小时**边缘缓存，当月小文件（2KB）实时取，两者按日期合并。

1. **策略切换完全失效**：原代码绑定的是 HTML 中并不存在的 `#btStrat`，点击 RSI / 突破 标签**没有任何反应**，参数区也不切换 —— 改为绑定 `.bt-tab`，并接入参数联动。
2. **胜率算错**：原实现用「平仓那一根 K 线是不是阳线」当胜率（≈50% 的噪声，与策略无关）。实测同一组数据：原实现报 **0%**，真实逐笔为 **50%**。现改为按每笔真实「入场价 → 出场价」结算。
3. **突破策略只买不卖**：原信号只有 0/1，开仓后**永不平仓**（等于一次性买入持有）。现改为通道双向：向上突破开仓、向下跌破平仓。
4. **最大回撤算错**：原用「全局峰值 − 全局最小值」，不区分先后顺序；改为标准口径（历史峰值→之后谷底）。
5. **夏普年化系数错**：原恒用 √252，与所选周期无关；改为按周期年化（15m/1H/4H/1D 分别 √35040 / √8760 / √2190 / √365）。
6. **样本太短**：原固定 220 根 K 线且锁定 BTC + 主图周期；现可选标的/周期并**拉满 1000 根**（日线约 3 年）。
7. **新增**：手续费（bps 可调）、**买入持有基准与超额收益**、年化收益、盈亏比、净值曲线双线对比、逐笔成交明细；数据不足或参数非法时**明确报错**而非静默无反应。
8. 信号在第 i 根产生、第 i+1 根**开盘价成交**，避免用当根收盘价的前视偏差。

### 模拟交易

1. **净值双重计成本**：原显示「初始资金 + 持仓市值」，买入 $1000 后净值**立刻从 10,000 跳到 11,000**（凭空 +10%）。实测：买入 1000 → 显示 11,000（应为 ≈10,000）；跌 10% 后显示 10,900（应为 9,900）。现改为「可用现金 + 持仓市值」。
2. **平仓后盈亏凭空消失**：原实现平仓只是把仓位删掉，**没有已实现盈亏字段**，浮动盈亏随即归零 —— 账户永远无法累积战绩（实测平仓后回到 10,000，亏损 -100 消失）。现改为真实结算并累计已实现盈亏、胜率。
3. **刷新丢账户**：原只把 positions 写入 localStorage，现金与盈亏不落盘；现**整账户持久化**（cash / realized / fees / 流水），并自动迁移旧数据。
4. **新增**：可用现金约束（超额开仓拦截并提示）、0.1% 单边手续费、买入均价合并、交易流水、已实现/浮动盈亏拆分、总收益率、**全部平仓**与**重置账户**按钮。
5. 开仓/平仓失败（无行情、金额非法、现金不足）时给出**明确提示**，不再静默无反应。
6. 修复平仓按钮：原按钮用了 HTML/CSS 中都不存在的 `qt-btn` 类，一直是**无样式的裸按钮**。

## v3.4 变更（更早）

1. **新增 5 个「事件因子」**：**非农就业（NFP）**、失业率、初请失业金、核心 PCE、CPI 月率 —— 取自**美国经济日历**的「实际 vs 预期」超预期幅度，按历史 surprise 标准差归一为 z-score；未发布时退化为「预期 vs 前值」（半权重）。因子总数 **21 → 26 维**。
2. **新增「美国经济日历」面板**：本周全部**中/高影响**美国事件的时间、预期、前值、实际（含非农、失业率、核心 PCE、初请、ADP、JOLTS、ISM、FOMC 讲话等）。
3. **原油因子升级为双源合成**：WTI（`CL=F`）+ 布伦特（`BZ=F`）滚动 z 均值；宏观卡片同时展示两者。
4. **数据源主备调换**：Yahoo Finance 升为主源，Stooq 降为兜底 —— Stooq 自 2026-10 起在 Cloudflare 边缘频繁返回 **522 / JS 反爬验证页**（实测），原「Stooq 主源」已实际失效（此前靠 Yahoo 兜底未被发现）。
5. **快照新增 `_src` 诊断字段**：逐序列记录实际生效的数据源，宏观面板底部实时显示「Yahoo Finance N 项 / Stooq N 项」。

> **关于非农 / CPI / PCE 的数据来源**：官方 BLS / FRED 原始序列从 Cloudflare 边缘被 WAF 拦截（BLS 403 / FRED 520，实测）；DBnomics 的 BLS 镜像虽然可达，但实测**数据只更新到 2025-01**（滞后 20 个月，不可用于实时）。最终采用 **Forex Factory 周度经济日历 JSON**（CF 边缘实测 200），提供非农 / 失业率 / 初请 / PCE / CPI 的**实际 · 预期 · 前值** —— 这是目前唯一「实时且边缘可达」的官方口径就业/通胀数据。

> **事件因子的方向约定**：就业强于预期 → 正 z；失业率/初请高于预期 → 负 z；通胀（PCE/CPI）高于预期 → 负 z（利率压力）。未发布时使用「预期 − 前值」的方向，权重减半并标注「未发布」。该映射是**约定**，非因果结论。

## 部署（Cloudflare Workers 整站）

整站由两个 Cloudflare Worker 组成，均通过 `routes.custom_domain` 绑定到 `uichain.org`（无需手动 DNS）。

### 1) 部署前端（Workers Assets 托管静态文件）

```bash
cd frontend
wrangler deploy          # 自动上传 public/ 并把 nexus.uichain.org 绑为自定义域
```

`frontend/wrangler.toml`：

```toml
name = "nexus-frontend"
main = "worker.js"
assets = { directory = "./public" }
routes = [{ pattern = "nexus.uichain.org", custom_domain = true }]
```

### 2) 部署数据 Worker（快照 + 代理）

```bash
cd worker
wrangler deploy          # nexus-api.uichain.org 自动绑定
```

`worker/worker.js` 暴露：

- `/api/snapshot` —— 宏观/政策/通胀/大宗/**日元**序列（DXY·US10Y·GOLD·SPX·VIX·OIL·BRENT·AGRI·**USDJPY**·EFFR·UST2Y·T10Y2Y·REAL10Y·BEI10·**JGB10Y**，含日期 + `_src` 数据源诊断），Yahoo 主源 / Stooq 兜底 + NY Fed + 美财政部 + 日本财务省；边缘缓存 15 分钟
- `/api/calendar` —— 美国经济日历（本周 USD 事件，含非农/失业率/初请/PCE/CPI 的实际·预期·前值）。成功结果边缘缓存 **6 小时**，距上次尝试不足 **30 分钟**则不再打 FF（退避），失败时返回**陈旧缓存**而非报错，并对 **XML 端点**自动降级；响应头 `X-Calendar-Source` 标明 `live / edge-cache / stale`
- `/api/global` —— 全球市值 / BTC 占比（coinlore 主源 → coinpaprika → coingecko 三级兜底，成功缓存 10 分钟 + 失败退避 5 分钟 + 陈旧兜底，响应头 `X-Global-Source`）
- `/api/history` —— 2 年长历史包（v3.8：Yahoo 2y + 美财政部多年 CSV + FNG + blockchain.info 交易数/算力 + EFFR/JGB），每序列 600 点截尾，输出 `coverage` 覆盖度诊断；降级（minLen<380）时缓存 TTL 3600s→300s，响应头 `X-History-Source`。**改动负载结构/语义必须提升缓存键 `history-vN`**
- `/api/fetch?url=<encoded>` —— 通用代理（白名单：Bybit / CoinLore / CoinPaprika / CoinGecko / alternative.me / mempool.space / DefiLlama / blockchain.info / Forex Factory / Yahoo Finance / **Japan MOF**），带 CORS 头；限流源做 10 分钟边缘缓存
- `/api/probe` —— 数据源可达性诊断（临时调试）

`app.js` 顶部 `CONFIG.PROXY` 指向：

```js
const CONFIG = { PROXY: 'https://nexus-api.uichain.org', ... }
```

若换域名，只需同步修改这一行并重新部署前端 Worker。

### 4) 源码同步到 GitHub（本机 git 因 xcrun 损坏，走 REST API）

项目根目录的 `push_to_github.py` 用 **GitHub REST API（git-database）** 整体推送，不依赖本地 git：

```bash
python3 push_to_github.py      # 全量刷新 main 分支（force 覆盖整棵树，GitHub 仅作源码镜像）
```

脚本会自动跳过 `.workbuddy / .git / node_modules / .wrangler` 与根目录 `public/`（旧 GitHub Pages 构建产物，已废弃；真正的静态资源在 `frontend/public/`）。Cloudflare 凭据走本机 `~/.wrangler/config/default.toml` 的 OAuth token。
